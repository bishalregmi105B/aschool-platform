## BACKEND CORE / AUTH / TENANCY (68 blueprints, 680 routes, 161 model classes, single migration head c7d9e1f3a5b2)

Route decorator coverage: 644/680 `@jwt_required`, 617 `@school_required`, 482 `@plugin_required`, 385 `@role_required`.

### P0
- **BC-1 Cross-tenant via `X-School-Slug`** (`app/__init__.py:339-345`): header sets `g.school_id` with **no comparison against the JWT's `school_id` claim** and no `user.school_id` check anywhere except `users.py`. A valid school-A token + `X-School-Slug: school-b` reads/writes school B. Subdomain resolution (`:330-337`) has the same hole. No regression test exists (`grep X-School-Slug tests/` → 6 hits, all same-school).
- **BC-2 CORS origin regex unanchored** (`app/__init__.py:107`): `rf"https://[^./]+\.{_re.escape(_base)}"` — flask-cors uses `re.match` (not end-anchored). Verified empirically: `Origin: https://demo.brighternepal.com.attacker.example` gets `Access-Control-Allow-Credentials: true`. The same list is the CSRF allowlist (`:483-489`) so CSRF is bypassed the same way. Fix: `^...$` anchors.
- **BC-3 Secrets fallbacks are literals** (`config.py:33,43` `"change-me"`/`"change-me-jwt"`), and `ProductionConfig.validate()`'s insecure-allowlist (`{"change-me","change-me-jwt",""}`) does **not** match the actual `.env` placeholder strings (`change-me-to-a-random-string`, `change-me-jwt-secret`) — **a production boot with today's .env passes validation using published placeholders**. Validate on length ≥32 + not-equal-to-example instead.
- **BC-4 `/api/v1/faqs` CRUD**: all 4 routes carry only `@jwt_required()` — any student/parent can create/edit/delete the school's public-website FAQs; `create_faq` writes `school_id=g.school_id` (None-able) → 500/None-scoped. (Cross-confirmed by website agent.)
- **BC-5 Token revocation fails open.** `RevokedToken.is_revoked` (`models/revoked_token.py:52,59`) compares naive `expires_at` column to aware `datetime.now(timezone.utc)`; wrapped by bare `except Exception: return False` in the blocklist loader (`app/__init__.py:93-97`) → **logout does not actually revoke; it silently fails open**.
- **BC-6 OTP expiry same bug** (`auth_service.py:124`) — `otp_expires_at` naive vs aware → TypeError → 500 on the DB-fallback OTP path. Also **OTP has no verify-side attempt limit** (`:111-157` deletes `otp_attempts` on success, never checks it) and comparison is not constant-time; OTP generated with `random.choices` not `secrets` (`:64`).
- **BC-7 Unguarded `.replace(tzinfo=...)`** (`assignments.py:360`, `plugins/billing.py:110` — the latter gates whether an expired trial can be reinstalled) vs the correct guarded form at `assignments.py:232-234`.

### P1 highlights
- **No rate limiting anywhere.** Zero `@limiter.limit` decorators; no `ProxyFix` (`grep` → 0) so behind nginx `get_remote_address` is the proxy IP for everyone — all tenants share one 60/min bucket. Fix: `ProxyFix(app.wsgi_app, x_for=1...)` + nginx `X-Forwarded-For $proxy_add_x_forwarded_for` + explicit limits on `/auth/login`, `/auth/send-otp`, `/auth/student-login`, `/auth/forgot-password`.
- **Cookie `Secure` computed from a config key that doesn't exist**: `auth.py:83-87` reads `current_app.config.get("FLASK_ENV")` — Flask 3 removed it and config.py never sets it → **`secure` is always False; production session cookies go over plain HTTP**. `JWT_COOKIE_SECURE=False` hardcoded (`config.py:56`).
- **TOTP secret stored in `user.permissions` JSONB and returned to clients** — `auth.py:682` writes `permissions["totp_secret"]`; `user.py:110 to_dict()` returns `permissions` wholesale → the shared secret is in `/auth/me`, `/users` list, and every login response; mass-assignable via `_populate_user`. MFA otherwise never enforced (`mfa_pending` cache key is read/deleted, never set).
- **Login has no index**: no index or UQ on `users.email`/`users.phone` → full scan per login + TOCTOU duplicate-signup race (`auth.py:432-437`).
- **83 `role_required(...)` lists omit `"superadmin"`** — the platform admin is locked out of features they support (concentrations: hostel 8, social_ads 8, reports 7, fees 11, exams 9).
- **Object-level authz missing on 204 read endpoints**: `/attendance/student/<id>` (any student reads any student), `/health-records/students/<id>` (**medical records** readable by any authenticated user of the school), `/portfolio/*`, `/gamification` points log, **`/hr_payroll/payroll/<id>/payslip` — any user downloads any staff member's salary PDF**, fee receipts (`fees.py:1496/1516/1532`), `/exams/marksheet/<id>` + `/report-cards/<id>` (per-student endpoints skip the teacher-scope filter the class endpoints have), `/exams/online/<id>/submit` (any student submits on another's behalf).
- **51 state-changing endpoints with no `@role_required`** — incl. `POST /database-backup/trigger` (school_admin triggers a **platform-wide pg_dump of all tenants**), files upload, procurement create, `POST /gps-logs` (inject bus GPS), dismissal verify-qr, LMS enroll/progress for arbitrary users.
- **51 GET list endpoints return `.all()` unpaginated** — incl. `super_admin.py:41` (all schools platform-wide), student attendance history, exams lists, fees lists. `utils/pagination.py` exists and is fine; unused.
- **N+1s in hottest paths**: `exams.py:921-952` results page ≈450 queries for 40×8; same pattern in report cards/bulk PDF (`:1416`, `:1559-1561`), fees receipts (`fees.py:460-462` etc.), design_studio data-sources, `_user_dict` in users list.
- **25 files with ≥5 `db.session.commit()` and zero rollback**; multi-step writes with no transaction boundary (`register_school` validates password strength *after* the school row is flushed → orphan school per weak-password signup; same in `update_student`).
- **P0-confirmed migrations gap (cross-confirmed by datamodel agent):** `student_scholarships` has no migration (scholarship endpoints 500; the discount application path is swallowed by `except: pass` at `fees.py:2415` so **students are silently billed full fees**); `designer_document_revisions` created without `is_deleted` but every query filters on it → `UndefinedColumn` on every revision save.
- **`ProductionConfig` boot guard only runs when `FLASK_ENV == "production"`** — the default is `development`, so an unset env boots with literal secret keys.
- Environment drift (verified): 8 keys in `.env` missing from `.env.example`; 26 in example missing from `.env`; 9 read by code but in **neither** (`SOCKET_MESSAGE_QUEUE`, `STRIPE_WEBHOOK_SECRET`, `NEXTJS_INTERNAL_URL`, `PLUGIN_TRIAL_DAYS`, `PLUGIN_FREE_TIERS`, `FILE_ALLOWED_EXTENSIONS`, `MAIL_TIMEOUT`, `PLATFORM_IP`, `PUBLIC_API_BASE_URL`); `BASE_DOMAIN` differs across `.env` (aschool.com.np), code default, and nginx (brighternepal.com) — three sources of truth.
- Dead modules: `app/utils/i18n.py` (no importer), `app/utils/permissions.py` (no caller), `app/utils/rate_limiter.py` (103 lines, never applied — duplicates flask-limiter), `app/extensions.py` alias re-exports `redis_client` **by value at import time → always None** (one task imports it this way).

## INFRA / CELERY / PAYMENTS / COMMS

### P0
- **IN-1 Twenty of 44 Celery tasks publish to a queue nobody consumes.** 20 task decorators declare no `queue=`; workers run `-Q default,ai,notifications,gps`; there is no `task_routes`/`task_default_queue` anywhere → Celery's default queue is `celery`, unconsumed. **Beat logs "Sending due task" while the work silently never happens.** Affected: attendance_alerts, library_overdue, payroll_monthly, analytics_aggregate, academic_rollover, streak_update, sitemap_rebuild, social_publish, **expire_trials** (trial expiry actually works only because of the request-path defense). Fix: `task_routes={"*": {"queue": "default"}}` + `-Q ...,celery` transition.
- **IN-2 No locking/idempotency on money+message tasks.** No redis lock anywhere; `celery-worker` effectively 1 worker (the `deploy.replicas: 2` Swarm key is ignored by compose) with concurrency 4; `acks_late` off. **Fee reminders re-run → every defaulter parent gets a second paid SMS+push** (no `last_reminder_at` state exists); beat uses a file-backed schedule with no volume → **container restart at 08:01 re-fires the 08:00 reminders**. Emergency listener blasts up to 1,000 SMS with no guard.
- **IN-3 Backups have NEVER run.** `pg_dump` is not installed in the backend image (Dockerfile installs `libpq-dev` only) → `FileNotFoundError` swallowed by `except Exception` → RPO infinite. Also unencrypted uploads to R2, count-based retention (30) that fails silently (`except: return 0`), the documented restore command (`pg_restore`) **cannot read the format produced** (`--format=plain` gzip → needs `gunzip | psql`), `uploads_data` volume has no backup at all, and `LAST_DB_BACKUP_AT` status is read from an env var nothing ever writes.
- **IN-4 WhatsApp webhook signature check is always skipped (fail-open).** `webhooks/__init__.py:339` `if current_app.config.get("WHATSAPP_APP_SECRET"):` — **that key is never defined in config.py** → guard always false → anyone can POST crafted Meta payloads (and trigger billable auto-replies). The GET handler 3 lines above was explicitly hardened to fail-closed; the POST has the inverted default.
- **IN-5 Stripe webhook has no event-id replay guard and no school-ownership check** — trusts `metadata.school_id` verbatim; a replayed `checkout.session.completed` permanently activates a plugin with no payment; also activates **any unvalidated slug string** (cross-confirmed by plugins agent).
- **IN-6 Refund flow: `fc.payment_status = "refunded"` is not a valid enum value** (`fees.py:1958` vs `fee.py:70`) → Khalti refund succeeds (money leaves the merchant account) then commit raises `DataError`; the ledger says paid-in-full. Zero refund tests.
- **IN-7 Callback outstanding math ignores fines/discounts.** `webhooks/__init__.py:591` computes outstanding from the raw base while `_apply_fee_payment` uses base+fine−discount → **a Rs 500 late fine is paid at the gateway and silently dropped from the ledger** (E183 was fixed in `_apply_fee_payment`; line 591 missed).
- **IN-8 SMS: no spend cap, no opt-out, no DND, no quiet hours, Nepali segments mis-costed.** Truncation `message[:480]` assumes GSM-7 (160/segment) but Devanagari is UCS-2 (**70/segment**) → a Nepali message costs 7× the estimate; `SMSLog` written by only 1 of 3 SMS abstractions (OTPs, emergency blasts, listeners invisible in credit accounting); Sparrow API called over **plaintext http**; one platform-level sender ID ("ASchool") for every school; no delivery-status tracking (`delivered_at` never set).
- **IN-9 Socket.IO has no connect auth** (cross-confirmed independently — my own finding): no `@socketio.on("connect")`; `join_school` accepts any `school_id` from the client → any browser/script receives that tenant's live GPS child-bus locations, emergency alerts, attendance/marks/fee events. School UUIDs are exposed throughout the API.
- **IN-10 Deploy is not zero-downtime and has no rollback**: migrations run **after** the new containers go live (`deploy.yml:213` after `up -d`); health check hits `/health` (static ok, ignores DB state) not `/ready`; `docker image prune -f` deletes the image you'd roll back to; `git reset --hard origin/main` destroys server state.
- **IN-11 Flower on 0.0.0.0:5555 with empty basic-auth** (`FLOWER_USER/PASSWORD` in neither `.env` nor `.env.example` → `--basic-auth=:`), bypassing nginx; task arguments contain phone numbers/message bodies/payment refs, plus the ability to re-execute `send_bulk_sms` (spend money).

### P1 highlights
- Partial-payment ledger is **a parseable substring in an admin-writable `notes` field** (`[partial_paid:NNNN]` in `FeeCollection.notes`; admins can overwrite notes via `PUT /fees/collections/<id>` → erase or inflate paid state). No ledger, no `amount_paid` column, no double-entry.
- Receipt numbering: `COUNT(*)+1` race, **not unique** (no UQ on `receipt_number`), and scoped per-collection so there is no school-level sequential series (IRD/audit expectation).
- GPS: `poll_firebase_gps` at 15 s overlaps itself (sequential per-bus HTTP, 60 buses > 15 s); **haversine bug** (`gps_processing.py:149` computes `lon2 - lat1`) → geofence alerts effectively random, pushed to admins every 15 s with no dedupe; `GPSLog` grows unbounded with no retention.
- Observability: Sentry is correctly wired (the best piece). **No logging configuration at all** (zero `dictConfig`/`basicConfig`/`RotatingFileHandler` — every `logger.info` is discarded at default WARNING level), no request IDs, no metrics, no alerting, no log aggregation; `/ready` exists and is correct but nothing uses it.
- OneSignal role filter builds a malformed filter chain (`onesignal_service.py:153-159`) → **a push targeted at one school's admins goes to every admin of every school** (cross-tenant notification leak). FCM legacy filter passes non-enum roles ("principal") → `DataError`.
- FonePay webhook scans every school in the platform per callback (O(tenants) full table + Python JSONB filter) on an unauthenticated endpoint.
- `.dockerignore` missing in both services → `.venv` (375 MB), `node_modules` (825 MB), `.next`, tests, probe scripts, seed data all ship in build context/images; containers run as root on floating base tags.
- `TZ` unset in all containers; tasks use `date.today()`/`utcnow()` while beat runs NPT → rollover fires on the wrong day (00:05 NPT = previous UTC day).
- No TLS anywhere (no 443, no certs, no ACME); docs reference an `nginx/ssl` mount that doesn't exist; Cloudflare→origin is plaintext.

## DESIGNER + WRITER (40 templates, fabric v6.9.1, WeasyPrint 63)

**Verified-by-execution P0s:**
- **DS-1 Custom properties lost on every save** — `useCanvas.ts` calls `fc.toJSON(CUSTOM_PROPS)` at 4 sites; **fabric v6's `toJSON()` takes no arguments** (`toJSON() { return this.toObject(); }`). Verified headlessly: names/data/locked all lost. Consequences: layer names die → Layers panel/undo-restore break after reload; `data.token` dies → **saved school templates' merge fields can never be re-filled**; `data:{type:'qr',value}` dies → server QR re-encode never fires; locks don't persist. - **DS-2 Every server-PDF style truncated by quote collision** — `document_renderer.py` builds `style='...'` with single quotes and embeds single-quoted CSS values inside.
