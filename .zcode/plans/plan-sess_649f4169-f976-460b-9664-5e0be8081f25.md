# ASchool Dashboard → aos-app UI Rewrite Plan

**Goal:** Rewrite the entire ASchool dashboard UI (OS shell, design system, UI kit, all ~58 dashboard modules, mobile iOS mode, popups/notifications/toasts) so it visually and behaviorally matches `/home/bishal-regmi/Desktop/Win7Css/aos-app`, powered by the real **11.css** package vendored into the repo. All real functionality (Flask API, auth/roles, plugin manifests, react-query, forms, i18n, Bikram Sambat dates) is preserved — only the UI layer changes.

**Branch:** new `feat/aos-ui-rewrite` off current head. Conventional commits, one commit per workstream/module batch.

---

## Workstream 1 — Vendor 11.css (foundation)

1. Copy the whole package `/home/bishal-regmi/Desktop/Win7Css/11.css/` (gui/ SCSS sources, build.js, package.json, dist/) into `frontend/vendor/11.css/`.
2. Add `"11.css": "file:./vendor/11.css"` to frontend package.json + `transpilePackages: ["11.css"]` in next.config.js (same setup as aos-app).
3. **Scoping is critical**: ASchool's current copy is `.win11`-scoped so the Fluent element styles (button/input/table) don't leak into login, auth, and public school-website pages. Import `11.css/dist/11.scoped.css` (every selector prefixed `.win11`) — the shell root already carries the `win11` class, and all dashboard pages render inside it. Verify auth + `/school/[slug]` pages are untouched.
4. Patch known 11.css gaps in the vendored `gui/` sources and rebuild with `node build.js`: missing `@keyframes w11-fade-in` (used by `.win11-modal-backdrop`), undefined `--w11-shadow-card` (used by `.aos-plugin-card`), missing base rule for `.win11-desktop-icon`.
5. Delete `src/styles/aos-theme.css`; keep `src/styles/aos-integration-overrides.css` (window-content containment) and keep load order: Tailwind globals → 11.css scoped → overrides.
6. Verify the latest hybrid classes exist after build (`macos-dock`, `aos-spotlight`, `aos-app-drawer`, `ios-*`, `animate-*`).

## Workstream 2 — OS shell rewrite (`components/aos/*`)

Component-by-component parity rewrite against aos-app sources, preserving ASchool integration (real roles from `useAuth`, plugin-manifest sidebar via `useInstalledPlugins`, window content mounting via `AOSModuleRegistry`, route→window virtualization, `aos_embed` iframes, i18n):

- `AOSDesktopShell.tsx` — shell composition, theme application (`data-theme` + `.dark` + `--w11-accent` + `--w11-acrylic-blur` on root), flyout state, keyboard shortcuts.
- `WindowManager.tsx` — aos-app window physics: rAF-batched drag/resize, 8-direction handles, snap-layouts popover on maximize hover, GPU-accel classes, active/inactive shadows, animate-window-in.
- `Desktop.tsx` (wallpapers incl. gradient set, marquee selection, right-click acrylic context menu), `Dock.tsx` (magnification, bounce, tooltips, running dots, pinning), `Taskbar.tsx` (running/focus underline indicators, tray, clock), `TopMenuBar.tsx` (menubar dropdowns, role badge, bell), `StartMenu.tsx`, `QuickSettings.tsx`, `CalendarFlyout.tsx`, `WidgetsPanel.tsx`, `NotificationCenter.tsx`, `SpotlightSearch.tsx`, `AppDrawer.tsx`, `AppSwitcher.tsx`, `RoleSwitcherModal.tsx`, `AOSIcons.tsx`, `types.ts`, and native apps `SettingsApp.tsx`, `AppStoreApp.tsx`, `PluginRunnerApp.tsx` (Settings gets the full aos-app treatment: wallpapers, 8 accent swatches, dock/taskbar/topbar options, blur slider, pinning manager — but persists via `useAppStore`/localStorage instead of demo state).
- Registry/adapter files (`AOSModuleRegistry.tsx`, `lib/aos-app-adapter.tsx`, `lib/aos-navigation.ts`) keep their contracts unchanged.

## Workstream 3 — UI kit rewrite (`components/ui/*` → 11.css classes)

Rewrite internals of the 42 shadcn/radix components onto Fluent classes, **keeping every public prop/export API identical** so no page breaks and react-hook-form/radix behavior is preserved:

button→`win11-btn`/`button.accent/subtle`, card→`win11-card`, dialog→`win11-modal-backdrop`+`win11-dialog`, dropdown-menu/popover→`win11-menu`/`win11-dropdown`, select/advanced-select/multi-select/entity-picker→Fluent listbox/menu, tabs→`win11-tablist/tab/tabpanel`, table→`win11-datagrid(-container)`, badge/status-pill→`win11-chip success/warning/error/accent`, tooltip→`data-tooltip` pattern, switch→`win11-switch`, slider→`win11-slider`, progress→`win11-progressbar`, skeleton→`animate-shimmer`, spinner→`win11-spinner`, sheet→`ios-sheet-modal` pattern, empty-state→`win11-infobar`, page-header/filter-bar→commandbar patterns, wizard→groupbox/tab steps, charts→token-colored. Avatar/separator/label/etc. mapped to `win11-persona` / typography classes.

## Workstream 5 — Dashboard pages: full per-page rewrite (~58 modules)

First create shared aos-app building blocks in `components/aos/kit/`: `AOSPageHeader` (window-content title + `commandbar-button` toolbar), `KpiCard`/`StatGrid` (auto-fit minmax colored stat cards), `FilterCommandBar`, `DataPanel` (datagrid wrapper), `FormSection` (`win11-groupbox`), `DetailSplit` (`aos-responsive-split`), `StatusChip`. These encode the aos-app page anatomy so every module rewrite is consistent.

Then rewrite every module page — **data logic stays byte-identical (queries, mutations, forms, zod schemas); markup, layout, and classes change to aos-app patterns**. Executed in priority batches, one commit per batch, each verified in desktop window + iframe-embed + mobile:

## Workstream 6 — Mobile iOS experience

Rewrite `MobileExperience.tsx`, `IOSControlCenter.tsx`, `IOSNotificationCenter.tsx` to aos-app parity: springboard with squircle icons, dynamic island, sheet-modal module pages (reusing the rewritten module pages), iOS control center with vertical sliders, home indicator.

Per batch: `npm run lint`, `npm test`, `npm run build`; browser walkthrough (screenshots) of desktop window mode, `aos_embed` iframe mode, plugin windows, role gating (admin/accountant/teacher/student), dark/light themes + accent switching, en/ne i18n, mobile viewport <768px; confirm no 11.css leakage on `/login` and public school sites.
